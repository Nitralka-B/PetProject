# PetProject: Макет банковской системы (Microservices)

Этот проект представляет собой учебный макет распределенной банковской системы, построенной на архитектуре микросервисов. Каждый сервис отвечает за отдельную бизнес-область и взаимодействует с другими через четко определенные API.

## 📁 Структура проекта

*   **`/profile`**: Управление профилями клиентов, аудит и логирование.
*   **`/account`**: Управление банковскими счетами (создание, просмотр баланса).
*   **`/transfer`**: Обработка денежных переводов между счетами.
*   **`/authorization`**: Аутентификация и авторизация пользователей (JWT, роли).
*   **`/antifraud`**: Проверка транзакций на мошенническую активность.
*   **`/history`**: Ведение журнала всех операций в системе.
*   **`/public-info`**: Предоставление публичной, не чувствительной информации (например, курсы валют, информация об отделениях).

## 🛠 Технологический стек

*   **Язык:** Java 17+
*   **Сборка:** Maven (файл `pom.xml` в корне)
*   **Контейнеризация:** Docker, Docker Compose
*   **Взаимодействие:** REST API, межсервисное взаимодействие (HTTP/gRPC)
*   **Базы данных:** Для каждого сервиса, вероятно, своя (PostgreSQL / H2)
*   **Дополнительно:** Spring Boot, Spring Security, Lombok, SLF4J для логирования.

## 🚀 Инструкция по запуску

### Предварительные требования

1.  **Java 17 или выше:** Установите JDK.
2.  **Apache Maven 3.6+:** Установите Maven для сборки проекта.
3.  **Docker & Docker Compose:** Установите для запуска в контейнерах.

### Способ 1: Запуск с помощью Docker Compose (рекомендуется)

Это самый простой способ запустить всю систему целиком.

1.  **Клонируйте репозиторий:**
    ```bash
    git clone https://github.com/Nitralka-B/PetProject.git
    cd PetProject
    ```

2.  **Соберите проект:** (Если Dockerfile настроен на сборку из исходников, этот шаг может не потребоваться)
    ```bash
    mvn clean package
    ```

3.  **Запустите все сервисы:**
    ```bash
    docker-compose up -d
    ```
    Эта команда поднимет все микросервисы и их зависимости (базы данных, брокеры сообщений и т.д.).

4.  **Проверьте работу:** Откройте браузер и перейдите по адресу `http://localhost:8080` (или другому порту основного/гейтвей сервиса). Статус контейнеров можно проверить командой `docker-compose ps`.

5.  **Остановка:**
    ```bash
    docker-compose down
    ```

### Способ 2: Запуск микросервисов по отдельности

Вы можете запускать и разрабатывать каждый сервис независимо.

1.  Перейдите в директорию нужного микросервиса:
    ```bash
    cd profile
    ```

2.  Соберите и запустите его с помощью Maven:
    ```bash
    mvn spring-boot:run
    ```

3.  По умолчанию сервис `profile` будет доступен на `http://localhost:808X` (порт указан в `application.yml/properties` этого сервиса).

4.  Аналогично запустите другие необходимые сервисы (`account`, `transfer`, `authorization`), каждый в своем терминальном окне.

## 🧩 Подробное описание микросервисов

### Микросервис **`profile`** (Разработан вами)

**Назначение:** Ядро для управления данными клиентов банка. Обеспечивает безопасное хранение, модификацию и отслеживание изменений персональной информации.

**Основные функции (Endpoints):**
*   `POST /api/profiles` – Создание нового профиля клиента.
*   `GET /api/profiles/{id}` – Получение информации о профиле по ID.
*   `PUT /api/profiles/{id}` – Полное обновление данных профиля.
*   `PATCH /api/profiles/{id}` – Частичное обновление данных профиля.
*   `DELETE /api/profiles/{id}` – Помечает профиль как неактивный (мягкое удаление).
*   `GET /api/profiles/{id}/audit` – Получение лога изменений (аудита) для конкретного профиля.

**Ключевые особенности:**
*   **Полный аудит операций:** Все действия `CREATE` и `UPDATE` автоматически записываются в отдельную таблицу/сервис аудита с указанием, *кто* (`actor`), *когда* (`timestamp`) и *какие данные* (`diff`) изменил.
*   **Централизованное логирование:** Реализован глобальный обработчик исключений (`@ControllerAdvice`). Все ошибки и исключения логируются в структурированном виде (SLF4J), что упрощает отладку в распределенной системе.
*   **Валидация данных:** Входящие запросы валидируются на уровне контроллера (`@Valid`).
*   **Безопасность:** Интеграция с сервисом `authorization` для проверки прав доступа к операциям.

### Краткое описание остальных микросервисов

| Сервис | Назначение | Ключевые функции |
| :--- | :--- | :--- |
| **`account`** | Управление финансовыми счетами. | Создание счетов, просмотр баланса, блокировка/разблокировка. |
| **`transfer`** | Движение денежных средств. | Инициирование перевода, его валидация, выполнение списания/зачисления через `account`. |
| **`authorization`** | Безопасность системы. | Выпуск JWT-токенов, проверка прав доступа (роли `USER`, `ADMIN`), интеграция с Spring Security. |
| **`antifraud`** | Анализ транзакций. | Проверка переводов на подозрительную активность (лимиты, необычные операции). |
| **`history`** | Журналирование событий. | Запись всех значимых действий (логины, переводы, изменения профиля) для отчетности. |
| **`public-info`** | Публичный API. | Предоставление некритичной информации (новости банка, FAQ, курсы валют). |

## 🔧 Конфигурация и настройка

*   Конфигурация каждого сервиса находится в его папке в файлах `src/main/resources/application.yml` (или `.properties`).
*   В этих файлах настраиваются: порты, URL-адреса для подключения к БД, адреса других микросервисов, параметры логирования.
*   Для Docker-запуска переменные окружения могут быть заданы в файле `docker-compose.yml`.

## 📝 Примечания для разработчиков

*   **Стиль кода:** В проекте используется `checkstyle.xml` для соблюдения единого стиля кодирования. Проверить код можно командой `mvn checkstyle:check`.
*   **Взаимодействие сервисов:** Сервисы взаимодействуют между собой по HTTP (REST) или через очередь сообщений (опционально). Убедитесь, что перед запуском сервиса `profile` запущен сервис `authorization`, если он требуется для аутентификации запросов.
*   **Логи:** Логи каждого сервиса по умолчанию пишутся в консоль. При Docker-запуске их можно просмотреть командой `docker-compose logs -f [service_name]`.
